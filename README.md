# Candidate Check

Локальный прототип приложения для короткой оценки кандидатов. Интерфейс построен на React 19, серверная логика — на Vinext/Next-compatible API routes, данные хранятся в локальной SQLite-совместимой D1 базе.

## Что уже работает

- старт без регистрации: кандидат вводит имя;
- общий лимит 10 минут и серверный лимит 60 секунд на вопрос;
- случайная выборка из четырёх пулов сложности;
- правильный ответ никогда не передаётся в браузер;
- за неверный ответ или таймаут добавляется ещё один неиспользованный вопрос той же сложности;
- итог: баллы, количество вопросов, верные ответы, ошибки, точность и время;
- анонимный рейтинг: в базе сохраняется только публичный псевдоним (`Анна П.`), полное имя не хранится;
- адаптивная вёрстка для desktop и mobile.

## Модель оценки v0.1

| Уровень | Вес | Стартовая квота |
|---|---:|---:|
| Базовый | 1 | 2 |
| Средний | 2 | 2 |
| Сложный | 3 | 1 |
| Экспертный | 10 | 1 |

Стартовый тест содержит 6 вопросов. Ошибка увеличивает фактическое число вопросов, но не продлевает общий лимит. Повторно один и тот же вопрос в рамках попытки не выдаётся. Если пул исчерпан, дополнительный вопрос не создаётся.

Текущая формула рейтинга: `сумма весов правильных ответов`; при равенстве выше кандидат, завершивший тест быстрее. Точность показывается отдельно и не умножает баллы, чтобы штраф за ошибку не применялся дважды: кандидат уже теряет балл и получает дополнительный вопрос.

## Локальный запуск

Требуется Node.js 22.13+.

```powershell
npm install
npm run dev
```

Откройте URL, который напечатает dev-сервер (обычно `http://localhost:3000`). Локальная база создаётся автоматически при первом API-запросе в project-local каталоге `.wrangler/`.

## Архитектурные границы MVP

- нет авторизации и административного редактора вопросов;
- нет восстановления активной попытки после перезагрузки страницы;
- банк вопросов пока заполняется seed-данными в `db/runtime.ts`;
- схема создаётся идемпотентно при первом запросе; SQL-миграция Drizzle хранится в `drizzle/`;
- публичная публикация пока не выполняется: проект рассчитан на локальную разработку.

## Безопасность перед публикацией

До внешней публикации нужны rate limiting, CSRF/origin-проверка для mutation API, политика хранения результатов, резервное копирование, защита административного контура и отдельная проверка supply-chain зависимостей. Полагаться только на скрытую ссылку — это не контроль доступа, а декорация.
