# Candidate Check v1.6.0

Функциональный релиз добавляет внутренний режим ИБ-челленджа без изменения кандидатского
теста. Участник использует свободный ник, проходит обязательный demo и отвечает на вопросы
категории «Информационная безопасность» в течение 15 минут с лимитом 60 секунд на вопрос.

## Что добавлено

- отдельные UI, API, таблицы D1, рейтинг и admin-аналитика челленджа;
- anti-guess scoring с весами сложности и нулевым ожиданием случайного ответа;
- серверные deadlines, идемпотентный старт и ответы, восстановление сессии после reload;
- ручное завершение без штрафа за текущий неотправленный вопрос;
- полный post-finish review и очередь комментариев к спорным вопросам;
- выборка без повторов по `question_id` и `dedupe_key`, с учётом прошлой экспозиции;
- challenge-таблицы в backup и integrity verification;
- Node.js `24.20+ <25` для локального запуска и CI.

## Rollout

В локальном `npm run dev` челлендж включён по умолчанию. В остальных окружениях флаг
fail-closed: необходимо явно задать `SECURITY_CHALLENGE_ENABLED=1`. CTA появляется только
когда флаг включён и пул ИБ-вопросов готов. Telegram для этого режима не используется.

## Миграция и откат

При запуске применяется additive-миграция схемы 18. Для быстрого функционального отката
выключить `SECURITY_CHALLENGE_ENABLED`: CTA и публичный контур станут недоступны, данные и
таблицы сохранятся. Удалять миграцию или challenge-таблицы при rollback не требуется.

## Проверка перед пилотом

Выполнить `npm run verify`, проверить `/api/challenges/infosec/config`, пройти попытку с
таймаутом вопроса и ручным завершением, затем проверить рейтинг, полный разбор, вкладку
«ИБ-челлендж» и JSON/CSV export в admin. Отдельно провести SME-review содержания ИБ-банка.
