# Управление банком вопросов

Начиная с v1.2.0 банк вопросов управляется из локальной административной панели. В v1.3.0 добавлены пакетные операции, справочник категорий, импорт/экспорт, черновики и контроль покрытия. D1 хранит рабочее состояние и историю ревизий; `db/questions.json` используется только для первоначальной загрузки пустой базы. После первого bootstrap перезапуск приложения не откатывает изменения администратора к содержимому JSON-файла.

## Основные правила

- Содержимое опубликованного `question.id` неизменяемо.
- Изменение текста, контекста, вариантов ответа, правильного ответа, темы, сложности или `dedupeKey` создаёт новую редакцию с новым ID.
- Предыдущая редакция сохраняется для истории и аналитики, но становится неактивной.
- Активация и деактивация не переписывают содержимое вопроса и создают новую ревизию банка.
- Каждая операция сохраняет полный snapshot membership новой ревизии и запись аудита без PIN и содержимого admin cookie.
- Два открытых окна не могут незаметно перезаписать друг друга: mutation принимает ожидаемую ревизию и при конфликте требует обновить данные.

Такой workflow намеренно немного строже обычной формы редактирования. Он сохраняет воспроизводимость уже проведённых тестов: вопрос в старой попытке всегда означает тот же текст, категорию, сложность и ключ ответа, что и в момент тестирования.

## Работа в интерфейсе

1. Войти через `/admin/login` и открыть вкладку «Банк вопросов».
2. Найти вопрос по ID, тексту, теме или `dedupeKey`; при необходимости выбрать тему, сложность и состояние.
3. Нажать «Открыть», чтобы увидеть полный текст, контекст, варианты, правильный вариант, состояние и историю редакций.
4. Для нового вопроса выбрать «Добавить вопрос», заполнить поля и сохранить.
5. Для смыслового изменения выбрать «Создать редакцию». После сохранения новая редакция становится активной, старая — неактивной.
6. Для временного исключения без изменения содержания использовать переключатель активности.
7. После изменения проверить сводку готовности банка. Если квоты теста или remedial-резерв нарушены, операция отклоняется и рабочая ревизия остаётся прежней.

Внутри банка доступны пять рабочих разделов:

- «Вопросы» — поиск, карточка, история и выбор строк для пакетной операции;
- «Категории» — создание, переименование и объединение категорий;
- «Импорт и экспорт» — read-only preview JSON, атомарное применение и выгрузка актуального банка;
- «Черновики» — сохранённые наборы операций с повторной проверкой перед публикацией;
- «Контроль» — матрица category × difficulty и очередь качества с переходом в редактор.

Правильный вариант показывается только в защищённой admin-панели. Analytics export по-прежнему не содержит текстов вариантов, правильных ответов, PIN, session token или Telegram payload.

## Категории и стабильный профиль отбора

Категория является управляемой сущностью, а не произвольной строкой. Имя нормализуется как `NFKC → trim → collapse Unicode whitespace → lowercase`, поэтому `Сети`, `сети`, варианты с неразрывным или двойным пробелом не создают дубли. Новый, редактируемый, импортируемый или массово переносимый вопрос обязан ссылаться на существующую активную категорию.

У категории есть неизменяемый `selectionKey`. Переименование меняет отображаемое имя и выпускает successor-редакции актуальных вопросов, но не тематическую квоту selector. Объединение переносит leaf-вопросы в целевую категорию и выключает источник. Если операция затрагивает актуальные вопросы, они и новая ревизия банка записываются одной транзакцией; для пустой категории меняется только каталог. Операции передают exact `expectedCategoryName`, поэтому устаревшая вкладка не переименует уже изменённую категорию. При ошибке не сохраняется ни одна частичная строка. Попытки, начатые до операции, продолжают работать со своим frozen snapshot и старым отображаемым именем.

Новая категория без `selectionKey`, присутствующего в `GENERAL_TOPIC_PLAN`, не получает обязательную тематическую квоту balanced-профиля. Это нейтральное состояние, а не запрет: обычный legacy-selector по-прежнему может выбрать её вопросы по сложности. Чтобы сделать категорию обязательной частью сбалансированного профиля, требуется отдельное версионированное изменение test config.

## Массовые операции и черновики

Для загруженных вопросов можно выбрать до 250 уникальных leaf-ID и одной операцией изменить категорию, сложность или активность. Изменение canonical content создаёт successor-ID для каждого затронутого вопроса; изменение только активности сохраняет ID. Итоговый snapshot и все audit events записываются одной D1-транзакцией.

Черновик хранит `baseRevision`, собственную метку `updatedAt` и список операций, но не влияет на candidate flow. Preview пересчитывает будущую готовность и покрытие без записи в вопросы, revision snapshots или аудит. Изменение, удаление и publish передают exact `expectedChangeSetUpdatedAt` и требуют совпадения не только текущей ревизии банка, но и версии самого черновика. Если банк, черновик или зависимая категория изменились в другой вкладке либо одна операция невалидна, весь пакет остаётся неопубликованным.

## Импорт и экспорт

Импорт принимает до 250 вопросов. Семантика `id` строгая:

- отсутствующий `id` создаёт новый вопрос;
- `id` актуального leaf-вопроса создаёт successor-редакцию при наличии отличий;
- неизвестный или уже заменённый `id` становится validation issue;
- fuzzy matching по тексту, теме или `dedupeKey` не выполняется.

`POST /api/admin/questions/import/preview` является строго read-only и возвращает детерминированный diff `added/revised/unchanged/invalid` с `changedFields` и связанным с ревизией preview token. Apply принимает тот же документ, token, CAS revision и idempotency key. Наличие invalid-строки блокирует весь импорт.

Bank export возвращает только актуальные leaf-редакции в стабильном порядке ID. `exportedAt` соответствует времени применения revision, поэтому два экспорта неизменившегося банка byte-identical. Это защищённый operational export и он содержит ключи ответов, необходимые для восстановления банка. В отличие от него analytics export по-прежнему никогда не содержит answer key или raw answers. Оба экспорта не содержат PIN, cookie, Telegram token/payload или имя кандидата.

## Валидация

Перед применением сервер проверяет всю будущую ревизию, а не только изменённую строку:

- ID — положительное целое число и не используется существующей редакцией;
- тема и формулировка непустые;
- сложность — `easy`, `medium`, `hard` или `expert`;
- от 2 до 5 непустых уникальных вариантов;
- правильный индекс находится в границах списка;
- длины prompt, context, choice и `dedupeKey` соответствуют общим лимитам;
- `contextType` и context задаются совместно;
- активные вопросы не создают явный или вероятный дубль без общего `dedupeKey`;
- пул сохраняет стартовые квоты и remedial-резерв;
- категория существует, активна и не конфликтует с Unicode-нормализованным именем;
- пакет содержит не более 250 уникальных leaf-вопросов;
- импорт и черновик построены именно от текущей ожидаемой revision.

Ошибка валидации возвращается как безопасный структурированный ответ. До успешной проверки D1 не изменяется и новая ревизия не создаётся.

## Конкурентные изменения и повтор запроса

Форма передаёт `expectedBankRevision`, полученный при загрузке банка. Категории дополнительно передают ожидаемое текущее имя, а черновики — ожидаемый `updatedAt`. Если другая вкладка уже применила изменение, сервер отвечает `409 bank_revision_conflict`, `category_conflict` или `change_set_conflict`; интерфейс обновляет данные, после чего администратор повторно сравнивает изменения. Автоматическое «последняя запись победила» запрещено.

Повтор одного и того же запроса после потери сетевого ответа не должен создавать вторую редакцию или второй audit event. Клиент использует стабильный mutation key, а сервер возвращает уже созданный результат либо применяет операцию ровно один раз.

## Хранение и восстановление

В backup входят:

- текущий указатель ревизии банка;
- immutable-вопросы и полные membership snapshots;
- связи predecessor → successor;
- журнал операций и существующая review history;
- справочник категорий со стабильными selection keys;
- опубликованные и неопубликованные change sets вместе с их элементами.

`ops:backup:verify` проверяет внешние ключи, единственность текущего состояния, ссылки редакций и отсутствие разветвления цепочки successor. Restore восстанавливает эти таблицы вместе с остальной D1. Старые analytics facts и завершённые попытки не переписываются при создании новой редакции.

## Матрица приёмки

| Сценарий | Ожидаемый результат |
|---|---|
| Создание | Новый ID активен, revision изменён, snapshot и audit event созданы |
| Редакция текста/темы/сложности | Старый ID сохранён и выключен, новый ID активен, predecessor/successor связаны |
| Активация/деактивация | Содержание и ID прежние, revision и audit изменены |
| История | Видны revision, timestamp и тип операции без PIN/cookie |
| Некорректное поле или неготовый пул | `400`, D1 и текущая revision не изменены |
| Устаревшая `expectedRevision` | `409`, чужое изменение не перезаписано |
| Повтор mutation key | Возвращён тот же результат без второй редакции |
| Запрос без сессии / CSRF | `401` / `403`, состояние не изменено |
| Перезапуск | Текущая D1-ревизия и активность сохранены |
| Историческая аналитика | Старый ID и его факты остаются в старой ревизии |
| Analytics export | Нет choices, correct answer, PIN, cookie и Telegram payload |
| Переименование категории | Leaf-вопросы получают successor-ID одной revision; selection key и readiness сохранены |
| Объединение категорий | Вопросы перенесены в активную цель, источник выключен, частичных изменений нет |
| Массовая операция | Все изменения и successor links опубликованы одной revision либо не опубликовано ничего |
| Import preview | Детерминированный diff, D1 и revision не изменены |
| Import apply/retry | Один atomic результат; повтор idempotency key не создаёт новые ID |
| Черновик publish после чужой правки | `409`, пакет не применён и остаётся доступным для проверки |
| Bank export | Только current leaf, стабильный ID order/exportedAt, нет runtime-секретов |
| Матрица покрытия | Active/current counts по category × difficulty и явные дефициты |
| Очередь качества | Переход открывает точную карточку вопроса в защищённом редакторе |
