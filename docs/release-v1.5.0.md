# Candidate Check v1.5.0

## Что изменилось

- После завершения теста кандидат получает разбор только реально показанных ошибок и тайм-аутов: свой ответ, правильный вариант и краткое пояснение. Непоказанные вопросы при общем тайм-ауте не раскрываются.
- В списке кандидатов администратор видит сохранённое имя новых завершённых попыток. Старые имена, ранее очищенные retention-политикой, отображаются как недоступные и не восстанавливаются.
- Карточка кандидата содержит полный журнал назначенных вопросов, статусы, выбранные и правильные ответы, время и баллы; можно переключаться между ошибками и всеми вопросами.
- Logout немедленно скрывает административный экран и повторно проверяет сессию при Back, `pageshow`, `popstate` и возвращении вкладки из background.

## Граница данных

- До завершения попытки correct answer не включается в candidate API.
- После завершения candidate API возвращает только ошибки среди показанных вопросов и остаётся защищён bearer-token попытки с `Cache-Control: no-store`.
- Полный журнал и имя доступны только detail endpoint действующей PIN-сессии администратора.
- Имена завершённых кандидатов теперь хранятся вместе с локальной попыткой до явного purge; Telegram payload и abandoned-данные продолжают очищаться автоматически.

## Проверки

- Unit/contract: маппинг статусов, исключение непоказанных вопросов, сохранение completed name.
- WebKit E2E: разбор ошибок кандидата, подробная карточка администратора и невозможность вернуть admin UI кнопкой Back после logout.
- Полный gate: `npm run verify`.
